# Commit Conventions

## 原则

每个 commit 只做一件事，小而专一，便于 review 和回溯。

## 提交规范

### 语言

Commit message 使用**中文**，描述清晰简洁。

### 格式

```
<类型>: <简短描述>

<详细说明（可选）>
```

### 类型

| 类型     | 说明                |
|----------|---------------------|
| feat     | 新功能              |
| fix      | 修复 bug            |
| refactor | 重构（不改变行为）   |
| test     | 添加或修改测试       |
| docs     | 文档变更            |
| chore    | 构建、工具、依赖变更 |

### 要求

- **一提交一改动**：一个 commit 只包含一个逻辑变更，不混合无关改动
- **描述简洁**：第一行控制在 50 字以内，说清楚做了什么
- **可编译**：每个 commit 之后代码应能编译通过，测试能运行
- **不提交未完成功能**：不提交半成品或调试代码

### 示例

```
feat: 添加 PR diff 获取功能

通过 GitHub Compare API 获取增量 commit 的 diff 数据，
支持文件过滤和 patch 内容提取。
```

```
fix: 修复 webhook 签名验证失败时的 panic

签名验证失败时改为返回 401 错误码，不再 panic。
添加对应的单元测试。
```

```
test: 为 context builder 添加 L0 层测试

覆盖 diff 获取、文件过滤、二进制文件跳过等场景。
```
